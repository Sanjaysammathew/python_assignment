Student Analysis Project Report

Project Information
- Project name: Student Analysis JSON
- Project description: A beginner-friendly Python project that stores student records and marks in JSON files, analyzes academic performance, and reports averages, grades, and ranking information.
- Technologies used: Python 3, Pytest, pytest-html, Pydantic, JSON file storage, async/await, logging.

Architecture
Router
  ↓
Service
  ↓
Repository
  ↓
Database

This project keeps the logic layered in a readable way. The service layer performs business logic and calculations, while the repository layer reads and writes the JSON files.

Pydantic
- Pydantic models are used in the Student and Marks domain models.
- Validation is defined with Field constraints for required values, minimum lengths, and numeric ranges.
- A custom field validator is used to reject blank student names, course values, and student IDs.
- Request-like data is validated before being used by repository or service methods.

Async/Await
- Async/await is used in the repository and service layer to handle file access without blocking the event loop.
- Database-style JSON reads and writes run through asyncio.to_thread, which is appropriate for file I/O.
- This keeps the project simple while still using async patterns correctly.

Logging
- Logging is configured once in config/logging_config.py.
- INFO logs are used for normal operations such as fetching students and calculating reports.
- WARNING logs are used for missing data or invalid operations.
- ERROR logs are used for invalid values and failed analyses.

Functional Programming
- map(): Used in get_subject_average() to transform marks into subject values before calculating the average.
- filter(): Used in get_passing_students() to keep only students whose average meets the passing threshold.
- reduce(): Used in calculate_total() to sum the subject values into a total using functools.reduce.

OOP
- Classes used: StudentAnalysisService, StudentRepository, MarksRepository, Student, Marks.
- These classes model the domain and keep business logic separate from file storage.
- This keeps the project class-based, readable, and maintainable.

Database
- The project currently uses JSON files as its storage layer.
- CRUD-style operations are handled in the repository classes.
- Students and marks are stored in data/students.json and data/marks.json.
